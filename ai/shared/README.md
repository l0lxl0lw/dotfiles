# Shared Agent Config

Canonical public skills consumed by Claude, Codex, and Grok. Skill
instructions, scripts, references, and shared libraries live here. The issue
tracking, evidence and delivery helpers the develop skills use live in `workflow/`.

```
ai/
└── shared/
    ├── agents/
    ├── workflow/
    └── skills/
        ├── develop/
        ├── explain/
        ├── external/
        ├── git/
        ├── learn/
        ├── orca/
        ├── remember/
        ├── respond/
        ├── sentry/
        ├── use/
        └── write/
```

`claude_merge_config`, `codex_merge_config`, and `grok_merge_config` flatten
`ai/shared/skills/**/SKILL.md` into their respective runtime skill directories.
Tool-local skills win by basename, so put a skill under `ai/claude/skills`,
`ai/codex/skills`, or `ai/grok/skills` when it needs tool-specific behavior.

`ai/shared/agents/` holds the workers the develop skills dispatch. Each is defined
once with a model tier and rendered into Claude Code and Codex agent
files; see [its README](agents/README.md).

## Naming and catalog

Use `<folder>/<folder>-<task>/SKILL.md`; the `name:` frontmatter must match the
skill directory. The folder prefix is explicit, not generated by the loader.
Folders use verbs, with `git`, `ghp` and `orca` as tool-specific exceptions.
Directories named `_lib` hold shared resources and are not skills.

Skills imported from other repositories go under `external/<source>/` and are
exempt from the folder-prefix rule: they keep their upstream names, or a local name
when that slash command already exists. Each import keeps its license, and each skill names its upstream link and pinned revision. Upstream
helper skills that the imported commands depend on live in that source's `_lib`, so
they do not become extra slash commands.

## Portability

Use the host's available tools: `AskUserQuestion` means its question dialog (or a
chat question if unavailable). Model/effort frontmatter can remain as Claude hints.
Resolve scripts and sibling libraries from the physical skill directory so symlinks
work. Git skills share `_lib/portability.md` for these conventions.
Code explanations and the two code-grounded learning exercises share
`explain/_lib/grounding.md` and `explain/_lib/explaining.md`; cross-folder references
resolve relative to each skill's physical directory.

Integration skills need the named MCP/application. Discovery exposes their
instructions, not missing dependencies.
Private adapters stay in private configuration and are never copied into public bundles.

The shared catalog contains 40 skills. The business, codebase, impeccable,
mattpocock, omc, utilities, and workflow families were removed after a usage review.
Their six workflow stage commands and seven dependent agents were also
retired. The development methods are now selectively revived in
[develop](skills/develop/README.md), using two public commands and four internal
fresh-worker agents. Profiles and the old commit stage remain retired. The catalog
is organized by intent in the eleven folders above, plus `external/` for imports.
`develop-prepare` consolidates feature/bug clarification, research, ticket and plan
on main. Explicit through-PR approval invokes `develop-deliver` in an Orca feature
workspace. The former standalone stages and `/brainstorm` alias are retired;
their useful methods and the Superpowers source/MIT license live in `develop/_lib`.
The former `make-html` skill was restored as `write/write-html`, including its
21 HTML examples and floating table-of-contents helper.
`external/ayghri/respond-adhd` imports the upstream `i-have-adhd` response-formatting mode,
with its source reference and MIT license preserved. Invoke `/respond-adhd` to enable
it for the session; say "stop adhd mode" or "normal mode" to turn it off.

`external/guillaumemeyer/use-watermarks-remover` imports the upstream `remove-ai-marks` skill from
[guillaumemeyer/watermarks-remover](https://github.com/guillaumemeyer/watermarks-remover),
with its pinned source revision, references, and MIT license preserved. Invoke
`/use-watermarks-remover` for Unicode, AI-provenance metadata, and best-effort
watermark cleaning of content you own or are authorized to process. It requires
a separately configured upstream HTTP service (`WATERMARKS_SERVICE_URL`, default
`http://127.0.0.1:8765`); importing or syncing the skill does not install or start
that service or its optional backends.

`external/mattpocock` imports `grill-me` and `grill-with-docs` from
[mattpocock/skills](https://github.com/mattpocock/skills) at revision
`5863806dd4e15c63174bee4e7515a4256792ecfa`, with the MIT license preserved. Their
upstream dependencies, `grilling` and `domain-modeling` (with its glossary and ADR
formats), live in `external/mattpocock/_lib`. `/grill-me` writes no files;
`/grill-with-docs` writes `GLOSSARY.md` and `docs/adr/` in the repository being discussed.
