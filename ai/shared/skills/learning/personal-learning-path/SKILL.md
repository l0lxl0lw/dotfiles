# Personal Learning Path

Design a learning path around a result, not around covering an entire subject.
This skill contains its own procedure and requires no other learning skill.

## Establish the learning contract

Collect the actual goal, desired result, deadline, available session length, and
what the learner already knows. Use supplied information and ask one compact batch
for missing details. Default to seven days of 45 minutes only if no schedule is
specified. Validate important claimed prerequisites with a brief practical question
when needed, without turning planning into an exhaustive exam.

Define a final observable demonstration. Distinguish learning to perform the task
from having the assistant produce the result. If the goal does not fit the time,
name the mismatch and negotiate scope or schedule; do not manufacture a guarantee.

For a named repository, inspect the relevant source, tests, and setup constraints
before choosing tasks; cite source paths for code-specific requirements. For other
topics, use the learner's materials and reliable references as appropriate. Label
assumptions and do not invent available tools, fixtures, or resources.

## Build backward from the final task

Each day has exactly one primary task fitting the agreed session length, with:

- A concrete output or performance the learner produces.
- A clear criterion for knowing whether it is correct.
- The prerequisite or gap it addresses and its connection to the goal.
- What to defer that day to prevent irrelevant work.

Budget setup, practice, and checking inside the time allowance. Sequence real
dependencies and reuse earlier outputs. Avoid vague assignments such as “learn
the framework” or “watch tutorials.” Include a later retrieval or transfer task
so the schedule does not rely solely on immediate repetition.

Before presenting the path, check that every task advances the result, no required
prerequisite is missing, and the final demonstration is feasible. Revise if not.
Present a compact daily table, the overall completion criterion, and the first step.

## Coach and adapt when the learner returns

Ask for the task's output or reasoning. Evaluate against its criterion. If it is
incomplete, identify the specific gap and adjust the remaining path rather than
automatically advancing. Preserve the goal and explain any schedule tradeoff.

End each coaching session with a short resume summary: goal, completed evidence,
remaining gaps, current day, and next task. Keep it in chat unless saving a local
learning record is explicitly requested. Do not edit application code, publish
artifacts, or schedule external reminders merely to generate a learning plan.
